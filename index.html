How it works

  1. Sender picks a file and gets an invite code — a description of their browser's network route.
  2. Receiver pastes it and sends back a reply code. These two codes let the browsers find each other directly.
  3. The file streams through an encrypted WebRTC channel in 16 KB chunks. No server ever sees the file — if the two peers can't find a direct route, the connection simply fails rather than falling back to a relay.

Works best between browsers on the same Wi-Fi or when both sides have permissive networks. Codes are long — that's the whole security model: whoever holds both codes holds the session.
